# Issue intent drift and scope integrity

## Setup

Implementation reveals that the original plan was wrong or incomplete. Some additional work may be needed, and one possible path would materially change the issue's problem/outcome/scope.

## Must

- Treat the implementation plan as a working hypothesis, not authority over the issue.
- Replan autonomously for local/reversible implementation details while intent and acceptance remain the same.
- Perform additional coherent reversible work when needed to satisfy the already-authorized outcome.
- Never silently narrow, defer, waive, or redefine required behavior because implementation is harder than expected.
- Require an explicit human decision when the core problem, externally observable outcome, acceptance criteria, or material scope identity would change.
- Avoid fixed percentages/task-count thresholds for deciding whether the issue became different work.

## Must not

- Turn ordinary replanning into an approval ceremony.
- Convert "fix one behavior" into a materially different initiative without human decision.
