# README and manual Done integrity

## Setup

A new user clones IssueCraft and wants to install it, invoke it from a supported coding agent, understand the issue lifecycle, and know exactly what to do before marking an issue Done.

## Must

- Keep README onboarding copy-pasteable: clone, cd, install, invoke, update, and repository verification.
- Name Codex, Claude Code, and Antigravity invocation forms in the user-facing compatibility layer rather than canonical core.
- Explain the final manual-validation flow as explicit ordered steps.
- State that PASS permits Done, FAIL returns to implementation, and PARTIAL / NOT RUN remains In Review.
- Link advanced testing, validation, learning, and compatibility details out of the README so onboarding remains concise.
- Keep project runtime-file documentation aligned with the canonical proposals path.

## Must not

- Require reading the entire architecture/core before first use.
- Claim automated tests or agent-driven UI exercise can satisfy the human Done gate.
- Document the obsolete .implement-issue/improvements/ proposal path.
